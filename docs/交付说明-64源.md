## 零、上一版为什么失败（已修）

**症状**：打开插件中心，红色报错
`state not managed for field 'host' on command 'hpp_manage'. You must call '.manage()' before using this command`，
「已安装 0」。

**根因**：`hghub_hpp::runtime::inspect()` 不是读源码文本，而是**新建一个 QuickJS 运行时把插件 `eval` 一遍**——
真执行插件的顶层代码，每个还有 5 秒超时。上一版在 `setup()` 里对 64 个插件挨个 inspect，
光这一步就把启动路径占满；`app.manage(PluginHost)` 排在它后面，还没执行，前端已经在调 `hpp_manage`，
于是报「state 没注册」。

**修法**（三处）：

1. **meta 改到构建期提取**——`build_builtin.mjs` 用 Node 把 64 个插件的 `meta` 对象求值出来，
   写进 `builtin/builtin_meta.json`（35 KB，与 `#[serde(rename_all="camelCase")]` 的 `Meta` 同构）。
   启动时只做一次 `serde_json` 解析，**启动路径上一个 QuickJS 都不起**。
2. **`app.manage()` 提到种插件之前**——`PluginHost::new()` 只存路径、零 IO，命令立刻可用，
   后面任何意外都不会再出现 "state not managed"。
3. **单个插件失败只跳过自己**——校验 id 与清单是否错位，坏的那条打 stderr，不影响其余 63 个。

**校验**：64 条 meta 全部通过 `Meta::parse` 的规则（id 字符集、版本三段、protocol==1、kind、settings 结构）；
APK 解包后在 `.so` 里 grep 到 `"linkDomains"` `"defaultHeaders"` `"allowInsecureHttp"`，确认 meta 清单编进去了。

| 域名已失效 | aowu、apple、jpyy、tiantian、wwgz |

**为什么还留着？** 当初黄果也是「本地打不开」，实测是 DNS 污染（本地解析到 `106.74.25.198` 拦截页），手机上用移动数据就通了。所以这些大概率不是源挂了，是这台构建机到不了。

### 怎么开

「我的 → 插件中心 → 已安装」→ 找到源 → 点右边的启用开关。开了还是空白，就是真挂了，关掉即可。

## 七、还想加源怎么办

两种方式，都不用重装 APK：

1. **导入单文件**：插件中心 → 导入 → 选 `.js` 文件。`HGhub-插件包-64源.zip` 解压后就是 64 个单文件，可以挑着导。
2. **订阅地址**：插件中心 → 插件更新与订阅 → 填 manifest 地址。比如
   `https://cdn.jsdelivr.net/gh/leohenshuai/hghub-plugins@main/manifest.json`
   （GitHub 直连被墙，用 jsDelivr 镜像）

## 八、这次做了什么（技术侧）

1. **改 `builtin.rs`**：原来 `const HUANGGUO_CODE` 单文件写死，现在读 `builtin_seeds.rs` 的 `SEEDS` 数组遍历种入。
   - 单个插件 inspect 失败只跳过它自己并打 stderr，不会连累其他 63 个
   - 每个 id 独立判断「索引里有没有」，已有的绝不覆盖（用户的启用状态、设置、Cookie 都保留）
   - 目录名做了 `..`、`/`、`\` 过滤
2. **新增 `builtin_seeds.rs`**（脚本生成，勿手改）：64 条 `include_str!`，每条带 `enabled` 初始值。
3. **构建验证**：`cargo check` 通过；APK 解包后从 `libhuangguo_client_lib.so` 里 grep 到 4k-av、Auete影视、独播库、多播 duobo、Gimy TV、Pornhub、糖心Vlog、主播视频等字符串，确认 64 个真进去了。
4. **兼容性验证**：64 个插件全部 ESM 语法通过；全部只调用宿主 v0.0.5 已支持的 API（`hg.http.fetch`、`hg.crypto.digest/hmac/aesEncrypt/aesDecrypt`、`hg.codec.*`、`hg.html.parse` 等），没有越界调用。

## 九、已知限制

- **本地探活不准**：构建机的 DNS 被污染，境外站和部分国产站测不出来。真实可用性以你手机上为准。
- **`duobo` 插件 307 KB**：内嵌了加密库，是这个包里最大的一个。
- **源站会挂**：这些是社区维护的第三方插件，源站换域名/改接口后插件就失效。失效了在插件中心停用，或者等上游更新后重新导入 `.js`。
- **黄果仍需 Cookie**：部分作品的播放地址和登录态绑定，要在黄果插件的设置里填官网登录后的 Cookie（旧版说明第二节有详细步骤）。
